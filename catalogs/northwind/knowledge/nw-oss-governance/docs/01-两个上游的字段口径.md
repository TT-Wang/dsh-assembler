# 两个上游的字段口径

治理台同时连两个上游:**OSV.dev** 回答"有没有漏洞",**deps.dev** 回答"许可证能不能用、实际装进来多少东西"。它们对同一个概念的写法不一致,下面每一条都是实测结果,不是推断。

## ecosystem / system 的拼写:同一份依赖清单要用两种拼法

这是最容易错、错了还不报错的地方。

| 包体系 | 给 OSV(严格区分大小写) | 给 deps.dev(不区分,回显大写) |
|---|---|---|
| npm | `npm` | `NPM` |
| Python | `PyPI` | `PYPI` |
| Rust | `crates.io` | `CARGO` |
| Go | `Go` | `GO` |
| Java | `Maven` | `MAVEN` |
| Ruby | `RubyGems` | `RUBYGEMS` |
| .NET | `NuGet` | `NUGET` |

**OSV 写错大小写不会当成"查不到",而是拒绝请求**:给它 `pypi` 会返回

```
{"code":3,"message":"invalid ecosystem"}
```

deps.dev 相反,`npm` / `NPM` / `PyPI` 都通,内部统一成大写;Rust 那一栏尤其要注意,OSV 叫 `crates.io`,deps.dev 叫 `CARGO`,两个字符串毫无字面关系。

结论:**同一份清单喂给两边之前必须各自转换拼写**,不能把一份拼法直接透传。

## OSV 的批量端点只回 id,不回详情

`querybatch` 的返回里每个位置只有 `{id, modified}`,没有摘要、没有严重度、没有修复版本。所以流程只能是两段:

1. **分诊**:整份清单批量查一遍,得到"哪些包命中了、命中哪些 id"
2. **深挖**:对命中的包逐个查详情,才拿到严重度与修复版本

不要指望一次批量就出治理结论。

批量的返回**按输入顺序位置对齐**,而且**零命中的位置是一个空对象 `{}`,不是缺位、也不是错误**。清单里第 3 个包没漏洞,结果数组第 3 项就是 `{}`。按位置读,不要按"返回了几条"读。

## 零命中不是错误

查一个库里没有记录的包,OSV 返回 HTTP 200 加一个空对象 `{}`(连 `vulns` 键都没有)。这表示"没有已知漏洞",不表示查询失败。

## 修复版本从哪里来

OSV 的可执行结论藏在 `affected[].ranges[].events[].fixed`:那是"升到这个版本就不受影响"。要注意:

- `SEMVER` / `ECOSYSTEM` 型区间给的是版本号,可以直接当升级目标
- `GIT` 型区间给的是 **commit 哈希**,对依赖治理没有直接用处
- 有些公告只给 `last_affected`(最后一个受影响版本)而没有 `fixed`,意思是**还没有修复版本**——这类要走"无可用修复"的处置路径

## 严重度有两种说法,可能只有一种存在

- `severity[]` 里是 **CVSS 向量**(如 `CVSS:3.1/AV:N/AC:L/...`),机器可比
- `database_specific.severity` 里是**定性标签**(`LOW`/`MODERATE`/`HIGH`/`CRITICAL`)

定性标签是 GitHub 审核过的公告(GHSA-)才有;来自其他来源的记录可能只有 CVSS 向量、甚至两者都没有。**不要因为缺定性标签就当成低危**。

## withdrawn 的公告不作为行动依据

记录里出现 `withdrawn` 字段表示该公告已被撤回。撤回的公告不进整改清单,但要在报告里留痕说明"曾命中、已撤回"。

## deps.dev 的版本列表顺序不是时间顺序

`versions` 数组按**版本字符串**排序,不是按发布时间。所以 `4.9.0` 会排在 `4.17.21` 后面(字符串比较里 `9` > `1`),取数组尾部会拿到多年前的版本。要"最近发布的版本",必须自己按 `publishedAt` 排。

## deps.dev 的许可证字段是参考信息,不是法律结论

`licenses` 来自上游注册表元数据的镜像。它可能与仓库里 LICENSE 文件的实际内容不一致,也可能为空。**它用来筛查和排序,不用来下合规结论**;真正的判定要看包内的许可证文本。

## 依赖闭包里有一个节点是被查的包本身

`:dependencies` 返回的 `nodes` 里,第一个节点的 `relation` 是 `SELF`——那是被查的包,不是它的依赖。统计直接/间接依赖数量时要先把它排除,否则每个包都会被算多一个依赖。
