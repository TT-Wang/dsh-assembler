# dsh-assembler 路线图(2026-08-23 定稿)

身份裁定(用户拍板):**assembler = 零件生态的搜索引擎,给主 agent 提供支持**。
四个面:搜索引擎(检索零件)+ 确定性印刷机(哑发射)+ 独立考官(黑盒验收)+
证据库(选型/验收台账)。选型的智力归主 agent;装配器只给事实,不做主。

实证基础:A/B(编排胜流水线,docs/campaigns/ab-orchestrated-10.md)→ 四形态探索

forms-bcdf-8.md)→ 超配病根定性为 **context 缺口**而非纪律问题 → 主 agent 九步
工作清单,三个真智力点:②取舍裁剪 ④persona ⑦探针出题。

## 阶段 0|形态转正(收官,~一晚)

把已定的架构落成默认产品:

1. **默认形态翻转**:`DSH_ASSEMBLER_MODE` 未设 = 检索形态(search_catalog +
   emit_preset + verify_preset,match_catalog 留作专家精排备用阀);旧一条龙
   显式 `=pipeline` 才开(自动化/回归后备)。
2. **②取舍的 context 补全**(治超配,零阈值零说教):
   - 检索结果带**价签**:每件的 prompt 税(工具说明书字节,从联邦缓存精确算)、
     进程数、凭证;
   - search 描述写**基线判据**:零件用于真实世界 I/O 与确定性硬计算;交付 agent
     的 LLM 自己能稳定做的(日期差/格式化/文本加工)不装;
   - **物理事实就地写**:frontend 条目自带"每 preset 仅首个模板生效";
   - 唯一硬闸:≥2 个前端模板直接报错(物理不可能,不是决策)。
3. **⑦出题辅助**:MARK_RULES 精要压成草图模板,进 emit 结果契约(发射完提醒
   "按此模板出题")+ verify 描述;目标草图过闸率 8/14 → ≥12/14。
4. **动用率报告**:verify 结果列"全程动用 X/Y 件 + 未动用清单"(考官顺手产出,
   实测证据;明写"探针只走主流程,未动用≠无用")。
5. **FDE 闭环**:verify_shared_data 哑工具(包 runSharedDataProbe,考官独立),
   多 agent 班子 = 主 agent 多次 emit + 同一 sharedDb + 跨 agent 共享数据探针。
6. **身份文档**:README/DESIGN 改写四面身份;C/D 战役归档标注复活条件
   (D:目录过数千条复议)。

**验收(转正门)**:8 场景确认轮,新默认 vs F 裸奔——零件数回 5-8 件/场、
墙钟保持 F 级(Σ≈1200s)、草图过闸 ≥12/14、缺口诚实度不掉、安全场景红线不破。

## 阶段 2|证据飞轮(搜索引擎的护城河)

  信号;
- **相似案例注脚**:检索结果尾部附"历史相似需求的 PASS 选型"(few-shot 回路,
  TODO 原案的检索化变形)。

## 阶段 3|规模触发(挂条件,不挂日期)

- 目录 >2000 条:BM25 + 向量混合召回(设计预埋);**match 复活**为检索后的 LLM
  精排(方向 4 的两阶段架构在此规模成立);
- 同功能零件 >5/簇:聚类折叠 + 证据默认推荐;
- 零件不再全在本机:目录升级为注册表,按需安装走 index-add 质检门;
- 目录数千条:D(ask_catalog 对话专家)复议。
