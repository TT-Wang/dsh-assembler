# dsh-assembler 路线图 v3（2026-08-26,宪法定稿后重写）

> v2(P0-P4:减法与耐久化/泛化第一台阶/生态吸收/范式两战,已大部完成)见 git 历史。
> 本版按宪法(docs/CONSTITUTION.md)的语言视角重排:**这是一门编程语言**——
> 语义模型决定正确性分工,成立条件决定生存件,演化次序决定刀的先后:
> **语法先于语义,语义先于库,表面只准变小。**

## 终态定义(语言 1.0 的五条判据,全部可验)

1. **表面收敛**:一个形态、一条交付路、约 10 个工具面;每个闸的报错过第二条判法
   (只读报错改得动);每条散文契约带模型代到期日。
2. **正确性闭环**:四种链接形态(会话/页面/共享账/触发)各有独立考官;UB 登记上的
   每一项,要么已收编成考官,要么永久诚实登记——没有第三种状态。
3. **标准库成立**:目录规模化生长,元数据完整到"选型零猜测";采购流水线常态吞吐;
   至少一条真凭证端到端跑通。
4. **语言可分发**:三件核(诚实目录·哑发射·独立考官)MCP 化,任何 harness 可用;
   交付物自包含、可重建、毕业零惩罚。
5. **有战绩**:三档泛化达标、与生成器阵营正赛有胜绩、第 30 天生命周期有纵向台账。

五条齐 = 1.0。之后**表面冻结,永远只长地板下**。

  scaffold 骨架 + 写手席;rag-qa/record-desk 降级为写手可抄的起始页与范例;
  emit_app/verify_app 五道门并进统一考官后,车道闸/分叉行随双车道一起消失。
- **0.3 文档对齐**(半晚):README 中英去掉全部死路教学;BACKLOG/TODO 结案标注。

考卷 v3 方向已冻结(C 档判据改命题实质、题面去车道指令、artifactName 进 JSON)。

## 阶段 2|类型系统完成态(报错与表面制度化)

- **报错逐闸过堂**:按第二条判法审每个闸的报错,不带修法与真实候选的补齐。
- **概念账制度化**:工具面/形态/via 数量钉进测试(数概念的钉),加一删一会红。
- **BARE 消融挂代际**:换模型代自动触发散文契约到期重审。

## 阶段 3|考官覆盖——收编 UB(与阶段 4 并行)

- DOM 层考(补"DOM 事件→SDK 调用"那一跳);
- 验收覆盖率(按能力清单驱动多路径探针);
- selfcheck 升纵向记分板 + 验中版本钉 + 同名重发强制快照(第 30 天台账基建);
- 四项永久 UB(persona 质量/页面美观/需求理解/host 不在)留登记,不假装能考。

## 阶段 4|标准库规模化(常态背景,永不下线)

- 采购批次常态化(候选:CalDAV 写、文档写、快递物流、A股行情),采→转→造纪律不变;
- 元数据补全:role 进供应链档案、价签全标定、服务脸/凭证事实全上检索行;
- **真凭证端到端**(等用户配 env 扣扳机)——生产可用最后一公里;
- 战役语料按绑定认领的机制修复;
- 规模触发挂条件不挂日期:目录 >2000 条 → 向量混合召回。

## 阶段 5|语言标准化与分发

- **装配器 MCP 化**:三件核成为任何 harness 的零件——语言脱离单一运行时;
- 独立态 scaffold(交付彻底脱离 host);
- sessionProjections 替轮询;移动车道(Expo CNG)远期挂起。

## 阶段 6|证明层(范式战,两战定音)

- **高难度 app 装配正赛**(含 vs Lovable 同题对打):若干高难度需求端到端跑通,
  量形状贴合、验收覆盖、迭代成本、毕业成本——证明 vibe assembly 作为更抽象的
  语言层稳定、高效、优雅成立;
- **第 30 天 app 版**:需求变更序列下,页面级重发 vs 重新生成的生命周期对照。

## 永不做(继承并新增)

可视化画布;手工包裹每个框架;为当代模型写永久散文;把铸造当个人即时需求的默认
动作;**在表面加概念而不删概念;开第二条路做同一件事**。
