## 校准轮(C1 单题,结果作废)

按 penguin benchmark-design 协议,首轮是探针:用来修考卷,其结果不进战绩。抓到
**两处我自己的错**:

1. **考卷与自家契约冲突**:我把 C 档预期写成"什么都不发射",但架构契约从来不说
   "拒绝",它说的是"把缺口暴露给用户、由用户拍板"。而驱动器见检查点一律答
   "按此装配"——我扮演了一个什么都点头的用户,于是 agent 把实时协同降级成轮询
   也就被我自己批准了。**修法**:C 档改坚持型用户(核心需求不许降级不许砍,做不到
   直说),让"诚实劝退"与"硬凑"产出可分辨的不同结果(分离预测)。
2. **C 档预算 10 分钟太短**,agent 还在干活就被掐,末段回复不完整。修法:20 分钟。

考卷 v2 冻结后再开正赛。

### 发现一:检索没问题,路由才是病根(与污染无关)

机械核查:配方在检索里**稳居第一**(手册问答→rag-qa 14.7 分;记账→record-desk
18.6 分),agent 也真搜了(A1 搜 6 次)。**它看见配方,仍然选择装 preset+模板。**

判读:**这是我们自己造成的车道重叠**。双面化落地后(sqlite 服务脸 + 记录台直连
台账),preset 那条路也能给毫秒级直连页面,对"记账网页"这类需求两条车道产出高度
重叠、而且 preset 还多送一个对话口——agent 选它并非不合理。**契约停留在重叠之前,
缺"两条都能覆盖时按什么选"的判据。**

预注册不改(A 档按预期就是 0/3 形态路由达标,如实记账),缺口另开工单。

### 发现二:契约让 agent 走一条沙箱够不着的路

三个耗满预算的题,末段全是权限报错:「沙箱拒绝在会话工作区外写入(预设目录在
~/.dsh)」「app 写共享库被拒」「整个 /Users/tangtao/code 树对沙箱不可见」(还把
用户名拼错,越挖越深)。查 wire:`session.create` **没有权限旋钮**,沙箱是 host
部署级策略——不是甲具参数写错,是结构问题:**契约让 agent 走造件/知识包管道
(scripts/index-add.mjs),而那条管道住在装配器仓库里,会话 bash 沙箱够不着。**

这条对真实用户同样成立,不是甲具独有。A1 是典型:它想把手册做成知识包,做不到,
15 分钟没走到验收。

## 两处修补(第一轮发现即修,commit 在第二轮之前)

1. **知识包管道搬上工具面**:新工具 `add_knowledge`——在 host 进程里执行,天生跨
   沙箱;检索门一分不减(实测拿编造片段「三十年质保」去骗,当场拒收并丢弃半成品;
   真片段「十八个月」「24 个月」才放行入库并登记条目)。造零件仍走 CLI(那确实
   需要仓库权限),但契约改为:**够不着就如实上报工单,不许手改目录**。
2. **车道判据进契约**:交出去的/纯页面型/要脱离 host 独立跑 → 配方;要留对话口/
   多张脸共账/要挂 agent 能力 → preset 双面。并要求**把选择理由说出来一行**;
   契约里写进了实测数字(3/3 该走配方的需求默默走了 preset)作为这条判据的由来。

补契约时第一次批量替换锚点没对上,**断言当场抛错拦住**——没造成"改一半"的静默
半改,机械闸门在替我干活。

## 方法论沉淀

- **预注册 + 校准轮**:考卷提交在结果之前;校准轮的作用是修考卷、其结果作废——
  这两条一起,才让"预期与实际不符"能被诚实归因(是考卷错,还是产品错)。
- **判卷全机器可查**:形态路由看工具轨迹,交付真假看独立复核(HTTP 状态、引用资产
  逐个取、行为考判定),动作路由靠解析 agent 自己写的考卷。P3 战役的老教训:
  对照实验里判卷员偏见比臂间差异更危险。
- **战役的产出不止胜负**:这一轮最值钱的两条都不是"agent 不行",而是**我们自己的
  设计债**(车道重叠、管道不可达)。
