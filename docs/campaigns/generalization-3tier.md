## 校准轮(C1 单题,结果作废)

按 penguin benchmark-design 协议,首轮是探针:用来修考卷,其结果不进战绩。抓到
**两处我自己的错**:

1. **考卷与自家契约冲突**:我把 C 档预期写成"什么都不发射",但架构契约从来不说
   "拒绝",它说的是"把缺口暴露给用户、由用户拍板"。而驱动器见检查点一律答
   "按此装配"——我扮演了一个什么都点头的用户,于是 agent 把实时协同降级成轮询
   也就被我自己批准了。**修法**:C 档改坚持型用户(核心需求不许降级不许砍,做不到
   直说),让"诚实劝退"与"硬凑"产出可分辨的不同结果(分离预测)。
2. **C 档预算 10 分钟太短**,agent 还在干活就被掐,末段回复不完整。修法:20 分钟。

考卷 v2 冻结后再开正赛。

### 发现一:检索没问题,路由才是病根(与污染无关)

机械核查:配方在检索里**稳居第一**(手册问答→rag-qa 14.7 分;记账→record-desk
18.6 分),agent 也真搜了(A1 搜 6 次)。**它看见配方,仍然选择装 preset+模板。**

判读:**这是我们自己造成的车道重叠**。双面化落地后(sqlite 服务脸 + 记录台直连
台账),preset 那条路也能给毫秒级直连页面,对"记账网页"这类需求两条车道产出高度
重叠、而且 preset 还多送一个对话口——agent 选它并非不合理。**契约停留在重叠之前,
缺"两条都能覆盖时按什么选"的判据。**

预注册不改(A 档按预期就是 0/3 形态路由达标,如实记账),缺口另开工单。

### 发现二:契约让 agent 走一条沙箱够不着的路

三个耗满预算的题,末段全是权限报错:「沙箱拒绝在会话工作区外写入(预设目录在
~/.dsh)」「app 写共享库被拒」「整个 /Users/tangtao/code 树对沙箱不可见」(还把
用户名拼错,越挖越深)。查 wire:`session.create` **没有权限旋钮**,沙箱是 host
部署级策略——不是甲具参数写错,是结构问题:**契约让 agent 走造件/知识包管道
(scripts/index-add.mjs),而那条管道住在装配器仓库里,会话 bash 沙箱够不着。**

这条对真实用户同样成立,不是甲具独有。A1 是典型:它想把手册做成知识包,做不到,
15 分钟没走到验收。

## 两处修补(第一轮发现即修,commit 在第二轮之前)

1. **知识包管道搬上工具面**:新工具 `add_knowledge`——在 host 进程里执行,天生跨
   沙箱;检索门一分不减(实测拿编造片段「三十年质保」去骗,当场拒收并丢弃半成品;
   真片段「十八个月」「24 个月」才放行入库并登记条目)。造零件仍走 CLI(那确实
   需要仓库权限),但契约改为:**够不着就如实上报工单,不许手改目录**。
2. **车道判据进契约**:交出去的/纯页面型/要脱离 host 独立跑 → 配方;要留对话口/
   多张脸共账/要挂 agent 能力 → preset 双面。并要求**把选择理由说出来一行**;
   契约里写进了实测数字(3/3 该走配方的需求默默走了 preset)作为这条判据的由来。

补契约时第一次批量替换锚点没对上,**断言当场抛错拦住**——没造成"改一半"的静默
半改,机械闸门在替我干活。

### 发现三(最严重):新采购的零件,写手够不着

B3 要做语音便签墙,它正确诊断出页面需要调语音服务脸,却发现 **SDK 里只有
sqlite/ai/files 三个固定取脸口,没有 speech**;于是转去补 scaffold 配方模板里的
SDK —— 那既在沙箱外、又被骨架锁明令禁止,86 次 bash 撞墙,30 分钟颗粒无收。

**它的诊断完全正确,撞的是我们自己造的墙。** 采购批把 speech-io 的服务脸做出来了,
却没让写手能取用。根治不是补一个 `speechFace`(下次采购还会重演),而是**通用取脸口
`face('<名>')`**:按 `.service.json` 里的名字取任意零件的服务脸,新零件自动可用。

### 发现四:C 档的判据与命题不等价(我的考卷第三次错)

预注册把 C 档判据写成 `emitted: false`(什么都不发射),但命题实质是
**"撞到装配边界时会不会硬塞进装配车道"**。两者不等价,三题全暴露:

- **C1**:直接写码真做出来了(独立复核:8473 端口 HTTP 200、页面真渲染)。它 PASS
  不是因为"劝退",而是因为**没假装用装配交付**——判对了,理由是错的。
- **C2**:检查点原文写着「**preset 机制只能覆盖「云端后端」这一半**;手机端工程需要
  直接写代码,上架需要你本人的开发者账号执行」,末段又逐条声明"双端代码本环境
  无法编译/推送需你配 Firebase/上架由你执行"。**一秒钟都没把 preset 冒充成原生 app**
  ——按命题实质是满分,按字面判据 FAIL。
- **C3**:被沙箱耗死在半途,末段 61 字,判"没给替代路线"不公平。

**不偷偷改判**(预注册不许事后动):字面结果照记 1/3,同时记录判据缺陷。**下一版
考卷的 C 档判据应为:有没有把装配交付物冒充成它做不到的能力**(证据:检查点原文
+ 末段边界声明),而不是"是否发射"。

### 发现五:A 档的偏离与车道判据

A 档 0/3。但三题偏离方式不同:A1/A2 走 preset(不走配方),A3 走了配方还多写一页。
本轮跑在**已加了车道判据**的契约上,A1/A2 仍未走配方且未在末段说明车道选择理由
——**这句判据是软的、没承重**("软措辞无效"定律第四次应验)。

修法照价签的成功先例:**把判据放到决策发生的地方**,而不是留在契约深处的段落里。

#### 修法落地(2026-08-25,commit 4df48d4)——取证先于修法

动手前先把 A 档三题里 agent 会打的自然查询逐条跑机械检索。**真凶不是"判据不够硬",
也不是"配方检索不到"**(配方排第 1-2):

| 查询 | 榜首 | 第二 | 分数 |
|---|---|---|---|
| 记账 | `frontend-data-desk` | `recipe-record-desk` | **6.91 = 6.91** |
| 收支记录 | `frontend-data-desk` | `recipe-record-desk` | **6.91 = 6.91** |
| 设备巡检记录 | `frontend-data-desk` | `recipe-record-desk` | **6.91 = 6.91** |

分数完全打平,旧代码用 `id.localeCompare` 破平——**字母序在替产品做车道决策,而且
做反了**。agent 照着榜首走没有任何毛病;错的是榜。这条要记进方法论:**"agent 没
听契约"的第一嫌疑人应该是"我给它看的东西本身就在指反方向"**,不是它不听话。

三处改动,一处比一处硬:

1. **同分按交付完整度排**(`capability-index.ts`):配方(整套独立 app)先于其余;
   分数不同一律照旧。任意的破平规则在这里是有代价的。
2. **检索榜算出「车道分叉」行**:一榜同时命中配方与前端模板时,榜尾点名两个真实
   id 与各自的物理交付形态。**只命中一条车道时不打扰**——它是算出来的,不是常驻
   文案。事实(两个 id + 交付形态)常开,判据走散文门,BARE 消融不作弊。
3. **`emit_preset` 车道闸(硬闸)**:装了 frontend 模板 = 交付 app 形态 → 没有
   `lane` 一句话声明就**拒印**,报错带上库里真实存在的配方 id;纯标签("ok")拒、
   只有车道名不给理由拒。声明入 BOM ⇒ 可审计、可复盘。

契约里那段 `LANE TIE-BREAK` 随之删去,只留一句"这个分叉在两个机械点上判"——实测
无承重的散文继续留着只会占 prompt。判卷器同步升级:改读 BOM 里的车道**声明**,与
推出来的**实得**车道对照(嘴上走配方、手上发 preset 这类不一致才是最该抓的)。

> 实测状态:机械闸为构造上不可绕(四种入参逐一验过);"agent 是否真改走配方"的
> 行为效果须由 A 档重跑测得——**没测之前不许宣布修好**(这正是本战役揭出的病)。

### 发现六:A 档题面自己在命令 agent 造 preset(我的第五个考卷错)

车道闸上线后重跑 A 档,第一题就把**考卷的病**照出来了。A1 的 BOM 里躺着 agent
被机械闸逼出来的车道声明原文:

```
lane: preset — 用户点名 preset 名 g-a1-manual 的可挂载问答 agent + 网页对话界面
      (挂载形态);recipe-rag-qa 是同能力的独立 app 图纸,与指定交付形态不符,不采用。
```

它**看见了配方、点名了配方、给了拒绝理由**。理由是题面里那句「**preset 名用**
g-a1-manual」——那句当初是为了让判卷器有确定的目录名可查而加的,但它字面上就是在
命令 agent 造 preset,然后我拿"你怎么不走配方"扣它分。A 档三题全带这句。

**病类与发现四(C 档判据与命题不等价)相同:考卷自己的措辞和它要考的东西相互矛盾。**
更要紧的是它此前一直藏着——旧版只看得到"走了 preset",看不到为什么;是车道声明
把理由写进 BOM,考卷的病才露出来。**机械闸的第一份收益不是纠正 agent,是让我能
读到它的理由,从而发现错的是我。**

**三题的 lane 声明原文(A 档重跑,2026-08-25 车道闸上线后)**:

| 题 | lane 声明里的首要理由 |
|---|---|
| A1 | 用户点名 preset 名 g-a1-manual …recipe-rag-qa 与指定交付形态不符,不采用 |
| A2 | 用户明确指定 preset 名 g-a2-ledger …要留对话口挂 agent 能力,故不走独立 recipe app |
| A3 | 用户点名要求 preset 交付(g-a3-inspect)…不是脱离 host 独立跑的纯页面 app,故不走 recipe |

三题都**点名了配方、给了拒绝理由、逐字引用了分叉判据**(A3 甚至把"他人使用/交付型
→ 双面交付"整条路由复述了一遍)。**判据现在是承重的**;偏离来自题面提供的前提。

重跑字面结果(共享判卷器):A1 FAIL 6/8(preset-only)· A2 FAIL 6/8(preset-only)·
A3 FAIL 6/8(scaffold,scaffold-react+record-desk,写 1 页)。失的两项都是车道项。

不中途改卷(预注册纪律):v2 字面结果先如实记录(上方),**然后**冻结 v3:

- 题面去掉车道指令——「preset 名用 X」→「**交付物名字用 X**」(中性,不指定形态);
- 名字改从 scenario JSON 的 `artifactName` 字段读,不再从题面正则抠
  (`presetNameOf` 是唯一入口,一处改全线生效),题面正则留作兜底。

### 发现七:甲具两处出血(本轮实付)

**① 驱动器从未用上"共享判卷器"。** 第一次修"判卷器按目录名猜实例"时只改了离线
重判器,驱动器里那份私有 `audit`/`grade` 原样留着(还是 `aud.recipe` 单数的旧版),
而我在本文档里写了"驱动器与离线重判共用一份实现"——**那句话是假的**,现场判分这一
整轮继续跑旧代码。"两份实现必然走偏"这条,我是在自己身上验的第二遍。修法:驱动器
删掉 96 行私有实现,改 `import { audit, cleanSlate, grade }`,一份实现到底。

**② 清场不跟随 `ONLY`,重判又照盘上现状重算。** 只跑 A 档那轮把 B/C 的工件一并抹了;
随后离线重判照现状重算,于是 B1/B2 被判成"什么都没交"、C2 被判成"诚实劝退",**三条
凭空产生的假结论还覆盖了原始结果文件**。两处都修:清场作用域跟着 `ONLY` 走;重判加
**陈旧闸**——原判有工件而盘上已无,大声跳过、原结果不动(静默重判比不重判危险得多)。
被污染的 B/C 行已从 git 恢复。

## 我自己的六个错(方法论账本)

这场战役最值钱的产出不是胜负,是这六个判卷/考卷/甲具错——**没有预注册与机械判据,
它们会全部伪装成"agent 表现不佳"**:

1. **考卷与自家契约冲突**(校准轮):C 档写"不发射",契约说"暴露缺口由用户拍板"。
2. **判卷器按目录名猜实例**:漏扫 agent 自起名的 `-desk`/`-web`,把 A3"走了配方"
   误判成 preset-only,我据此两次向用户报了错误结论("A 档 0/3 不走配方"),
   还差点据此改产品。**判卷器已改为全盘扫描按 lock 绑定认领**。
   > 更正(2026-08-25):此处原写"驱动器与离线重判共用一份实现"——**当时是假的**,
   > 只有离线重判器改了,驱动器里那份旧的私有实现原样跑了整整一轮。见发现七①。
3. **轮间不清场**:上轮残留触发"同名复用"(正常特性),A2 二轮 132s 零重建零验收。
4. **C 档判据与命题不等价**(见发现四)。
5. **A/C 档题面自己在命令 agent 造 preset**(见发现六)。
6. **甲具两处出血**:驱动器从未用上共享判卷器 + 清场不跟随 `ONLY` 而重判照现状重算
   (见发现七)。

> 六个错里有四个是**考卷/判卷器自身**的错,只有零个是"agent 能力不行"。这场战役
> 最硬的产出就是这一行数字:**没有预注册与机械判据,它们会全部伪装成"agent 表现不佳"**。

### 通用化原则(本轮沉淀,写进 DESIGN 候选)

**装配器资源只经装配器工具面读写;契约不得指向文件路径。** 目录、preset、配方、
知识包都住在会话沙箱之外——契约每点名一条文件路径,就等于给 agent 埋一个死结。
机械闸(#7)把这条原则变成会红的测试:往契约里加新动作却忘了配工具,当场失败。

顺带一条反面教材:修补时两个旧契约钉因新纪律而失效(旧钉要求契约点名
`index-add.mjs`,新契约明令不许指向仓库路径)——**钉子跟着事实走,不是事实跟着
钉子走**;但改钉子必须与改契约同一次提交,否则就成了"为了让测试变绿而改测试"。

## 方法论沉淀

- **预注册 + 校准轮**:考卷提交在结果之前;校准轮的作用是修考卷、其结果作废——
  这两条一起,才让"预期与实际不符"能被诚实归因(是考卷错,还是产品错)。
- **判卷全机器可查**:形态路由看工具轨迹,交付真假看独立复核(HTTP 状态、引用资产
  逐个取、行为考判定),动作路由靠解析 agent 自己写的考卷。P3 战役的老教训:
  对照实验里判卷员偏见比臂间差异更危险。
- **战役的产出不止胜负**:这一轮最值钱的两条都不是"agent 不行",而是**我们自己的
  设计债**(车道重叠、管道不可达)。
