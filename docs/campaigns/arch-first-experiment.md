# 架构优先 A/B 实验 + 落地(2026-08-22)

用户提的架构问题:做 agent 最重要的第一步是**先定整体架构出 spec**,再选型、补缺口;
而 assembler 是**选型优先**(一上来锚定目录挑能力)。用户裁定:小跨度验证,证明更好就直接改。

## 实验:3 个复杂需求,A(选型优先)vs B(架构优先)

flag 门控的 `spec_experiment` 工具,拿真实 ctx.llm 跑两条路对照。

| 需求 | A 选型优先 | B 架构优先 | B 挖出的真缺口 |
|---|---|---|---|
| HR 全家桶 | 7 能力 / **0 缺口** | 27 / 3 缺口 | 身份认证RBAC、考勤规则引擎、制度语义检索 |
| 科研助手 | 22 能力 / **0 缺口** | 21 / 4 缺口 | 参考文献抽取、引文关联、章节切分、OCR 栅格化 |
| 医院导诊 | 5 能力 / **0 缺口** | 9 / 5 缺口 | 意图分类、症状抽取、导诊推理、**急危重症识别、边界拒答** |

**铁证:选型优先三战三次报"0 缺口"**——每次宣称目录完全覆盖,静默丢弃真需求,
医院导诊连**安全刚需**(急危重症识别、边界拒答)都漏了。架构优先在最要命的维度
(发现被静默丢弃的架构需求)完胜。代价:B 有过度选型嫌疑(HR 选了 27 个)。

## 落地(不照抄 B 的选型,只借它的缺口发现)

选型前先跑 `deriveArchSpec`(不给目录列全需求)→ 把需求清单钉进选型 prompt,
逼选型"逐条覆盖或标缺口、不许静默丢",仍取最小覆盖集。

**端到端实证(医院导诊,架构-first 进主路径后)**:
- 架构 spec 就绪:18 项架构需求(+15s,约选型 6%)
- 选型完成:9 能力 / **1 缺口**(external-api-service,对接医院挂号系统)——不再是 0!
- 分流正确:缺零件的进工单(API),缺行为的进 persona——persona 实测含
  "严格安全边界:绝不输出诊断用药建议;诊疗类请求转免责提示建议线下就医"、
  "从患者口语提取症状关键词/持续时间/严重程度"、"科普必须调检索并标出处"。
  实验中 B 报成缺口的安全/行为需求,集成版正确路由进 persona 兜住了。
- 装配 PASS,前端验收 PASS。

集成版比裸实验 B 更聪明:区分"要零件"(进缺口)与"要行为"(进 persona),
只把前者当缺口 → 完整覆盖架构需求,又不过度选型。

`DSH_ASSEMBLER_ARCH_FIRST=0` 可退回纯选型优先。实验工具保留在 arch-spec.ts,
`DSH_ASSEMBLER_EXPERIMENT=1` 才注册,供日后 A/B。
