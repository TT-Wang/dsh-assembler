### 取证:病根是入口随税一起死了,不是 agent 不行

- 装配器插件在战场 host **活着**(console 路由 200、工具面注册在案)——agent 是
  **主动绕过**了装配语言。
- v2 战役(08-25)跑在完整契约散文上,agent 全部走装配流;16fadf1(08-26)把
  工具描述 16014→4906 字符,被删的 `ARCHITECTURE_CONTRACT` 里**同时**装着:
  入口路由(什么形状的需求进装配语言)、架构先行、检查点纪律(ask_user_question
  呈架构+缺口)、资源只经工具面。删税删得对(那段挂在描述里,**每轮每会话**都付
  3174 token,含从不装配的会话);但入口线索是税的乘客,随车一起没了。
- 于是 A1/A2 的 agent 面对「帮我做个记账网页」,看到的 search_catalog 只是
  "零件搜索引擎"——没有任何在场事实说明这类需求该进装配语言,它就做了 coding
  harness 的默认动作:写代码。0 次检查点,0 次装配工具调用。

### 修法(结构,不是把税交回去)

按宪法第三条(规范住编译器:每轮 prompt=税,结果里出现=信息)拆开两半:

1. **入口一句留在描述**(全会话税压到 ~40 token,不可再减的路由事实):
   search_catalog 描述头挂 "START HERE when the user asks to BUILD… — NOT with
   hand-writing code"。
2. **流程契约整体搬进检索结果**(`ASSEMBLY_BATON`,prose 门内、BARE 可剥):
   架构先行→检查点(缺口三选:造件/降级/砍)→逐需求检索→emit(缺口进工单)→
   独立验收→页面两形态→资源只经工具面→个人即时型豁免。只有真装配的会话才付,
   是信息不是税。
3. 契约到期制照登记(CONTRACT_TAGS +ASSEMBLY_BATON,概念账 3→4 条承重散文,
   概念账钉同步);入口线/接力棒/BARE 剥离全部入测试钉。
