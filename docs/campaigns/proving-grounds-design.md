# 阶段 6 正赛设计草案:「试炼场」高难度装配战役(2026-08-27 起草,未预注册)

> 地位:**设计草案,不是考卷**。考卷(JSON,机器判据)在阶段 3/5 落地后写,
> 经附则「评测先受审」独立对抗审计 + 冻结预注册,方可开跑。本文件先钉命题、
> 判据框架与题型池,把"什么叫证明范式成立"从口号变成可判定命题。

## 一、命题(goal 原文的可判定化)

「执行若干高难度 app 装配测试,证明端到端完美跑通,vibe assembly 范式成立,
作为一门更抽象的高级编程语言系统可以稳定、高效、优雅运行。」

四个形容词各配一个机器可查的量纲(拒绝口号):

| 口号词 | 量纲 | 证据源 |
|---|---|---|
| **稳定** | 同题重跑 K 次(K≥2)判定一致;考官亲笔判定零翻案(字面=硬化) | selfcheck-history / repo 台账 / 重跑方差 |
| **高效** | 墙钟与 token 对照基线(徒手写码同题对照臂,或 v5 同档中位数);装配语言的"省掉一类活"必须在成本上可见 | tokenUsage 真通道 + elapsedSeconds |
| **优雅** | 不可直接判(UB 诚实登记)。代理量纲:概念账不涨(工具面 ≤12)、零打补丁通关(战役期间 src 无 hotfix 提交)、报错零死胡同(过堂三问全格率) | git log + 概念账钉 + 过堂底册 |
| **端到端完美** | 每题硬化判据全绿(考官亲笔判定 ∈ 预期、字节绑定、发布对账),且**零人工干预**(driver 全自动,无中途修法) | 硬化判卷器(v5 仪器) |

「范式成立」= 上述四量纲在**高难度题池**上同时达标,且失败题(若有)的病因
定位到语言缺口并进修法议程——失败不丢脸,**说不清失败才丢脸**。

## 二、与泛化战役的关系

- v4/v5 是**语言验收门**(阶段 1):三档九题,考"表达力没被语法收缩伤到"。
- 试炼场是**证明层**(阶段 6):少而重(4–6 题),每题都要压多个子系统同时工作,
  考"整个语言栈在真实复杂度下的合奏"。判卷器复用 v5 仪器(判定工件为法、
  硬化判据、examSha 双闸、finalTextComplete、语料/清场纪律),不另起炉灶。
- v6 议程三修(路线词表双语/暂存区证据面/预算-造件匹配)在试炼场考卷里直接
  按新法写(它没有 v5 的封存包袱)。

## 三、题型池(高难度 = 多子系统合奏,草案,终卷取 4–6 题)

1. **多面班子**(压:共享账 + 触发面 + 页面)——"进销存台:入库员 agent 记账、
   老板看板页读同一份账、每天 18:00 自动盘点并把缺货写进告警表"。判:
   verify_shared_data 班子考 + verify_trigger 无人值守考 + 发布对账,三面同账。
2. **知识重装**(压:kb + 检索门 + 增量重发)——"客服 agent 装 A 手册上线;
   追加 B 手册补货重发;旧问答不回归"。判:检索门两轮、同名重发快照在场、
   kbBound 双包、重发后考官判定字节绑定新代。
3. **写手极限页**(压:scaffold 自由区 + 行为考 + DOM 层考(若阶段 3 落地))
   ——一个范例页完全盖不住的交互形状(如:双栏拖拽排班表,拖动即写库)。
   判:五门 + face 效果断言 + 覆盖率;resembles 相似度必须低(证明不是抄范例)。
4. **采件即战力**(压:目录规模 + 联邦检索 + 新采零件)——用到本周新收的
   stock-sdk:"自选股盯盘台:页面展示行情 + agent 定时把异动写观察日志"。
   判:BOM 含 mcp-stock-sdk-* 面、触发面真跑、行情数字与上游一致(考官独立
   拉上游对数,允许延迟容差)。
5. **形外压线**(压:诚实边界)——一题略超能力面(如需要真推送),判命题实质:
   发射能做的部分 + gaps 工单 + 边界送达用户(v6 新法:工件级路线证据)。
6. **生命周期微缩**(压:迭代回路;第 30 天战的先遣)——同一 app 连续 3 个
   需求变更(加字段/改规则/换页面布局),判:每轮页面级重发而非重装、快照链
   完整、迭代墙钟递减或持平。

## 四、判据框架(每题四层,全部机器可查)

1. **字面层**:预注册 expect(lane/工件/路由计数……v5 语义);
2. **硬化层**:考官亲笔判定 ∈ 预期 + 字节绑定 + 发布对账(v5 仪器原样);
3. **合奏层**(新,试炼场特有):跨子系统一致性断言——同账双面读数一致、
   触发效果落库、行情对上游、重发代际链条完整;
4. **成本层**:墙钟/token 入档,对照臂或历史中位数,序数断言按形态分层
   (v5 教训:不混层判)。

## 五、开跑前置(依赖清单)

- [ ] 阶段 3 验收覆盖率落地(题 1/3/4 的多面判定靠它)
- [ ] 阶段 3 DOM 层考落地或明确裁"不进本战役"(题 3 的判据边界)
- [ ] 阶段 5 至少 sessionProjections(直播台不轮询,战役观测便宜)
- [ ] v6 议程三修进考卷语义(路线词表/暂存区/预算匹配)
- [ ] 驱动器沿用 v5(examSha/corpusDirs/finalTextComplete/hostEnv 全套)
- [ ] 考卷 JSON 写毕 → 独立对抗审计 → 修毕 → 冻结预注册 → 开跑
- 等用户(不阻塞其余):真凭证 env(题 4 若用凭证行情可升级)、Lovable 对打
  (正赛的对照臂之一,形式与预算归用户)

## 六、不做什么(先钉住,防设计膨胀)

- 不为战役新增任何工具面(概念账 12 是「优雅」量纲的一部分);
- 不造战役专用判卷魔法——判据必须全部落在产品工件上(考卷只读工件);
- 不把「优雅」偷换成主观评分——UB 登记的就留在登记里;
- 题数不超 6:少而重,每题失败都要能定位到子系统。
