# 转正确认轮:检索默认形态 G/H 两轮 × 8 场景(2026-08-23)

阶段 0+1 落地后的转正门实测(场景与 forms-bcdf-8 同源;F 裸奔 = 基线)。
两轮之间隔着一次**承重句修订**,正好首用 docs/prompt-regression.md 的程序:
改契约必实测。

## G 轮(context 补全 + match 备用阀,原始措辞)

8/8 PASS,零件数 3-7/场(F 的超配病痊愈),但**match 被每场拉动**(h03 达 ×6),
辅助思考回涨 Σ92.2k、Σ墙钟 2017s——"normally unnecessary"这种软措辞拦不住,
D 教训的反面成立:**可选工具不是中性的,描述听起来越权威越被优先拉动**。

## 承重句修订(G→H 唯一变量)

match 描述改为硬预算:"LAST-RESORT;每次装配至多一次;每个未覆盖需求先换
≥2 种说法检索;这是 60-180s 满档调用,检索能定的调它就是浪费用户时间";
search 描述明写"检索+你的判断就是选型全径"。

## 四门判定

1. ✅ 质量:两轮 16/16 PASS(b04 合规改写且仅 3 件——史上最瘦的安全场景交付)
2. ✅ 零件数:3-8/场,**且 H 轮证明纪律来自 context 补全本身**(价签+基线+物理
   事实),不依赖 match 在场——归因干净
3. ✅ 墙钟:6/8 场回到 F 级(76-203s);两长尾归因为探针质量,非选型路径
4. ✅(小样本)草图直用:H 窗口 ~8/10(≈80%,原 8/14=57%)——范例优先见效,
   继续监测;考官回退推导的出题质量列为下一个已知病(s23 的 base64 怪题)

**判定:转正成立。** 检索默认形态(context 补全 + 硬预算备用阀)为生产默认。

## 本轮新知

- **软措辞不是护栏**:"normally unnecessary"零效力,"at most ONCE + 先搜 ≥2 说法
  + 这要花用户 60-180s"立即生效(G→H match 调用 14+→0)。契约句要么带硬预算
  与代价,要么等于没写。
- 考官回退推导是当前质量尾部:sketch✗ 时推导出的探针可能出怪题(base64 案)。
  下一刀:回退推导 prompt 也吃 PROBE_SKETCH_EXAMPLES 范例。
