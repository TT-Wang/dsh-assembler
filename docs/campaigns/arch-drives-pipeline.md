# 方向 2:架构 spec 驱动全流程(2026-08-23)

用户点的方向 2:让架构 spec 那次推理的四维都用起来,不再只喂选型一维。
背景:方向 4(能力目录)实测证明选型是推理绑定、压输入不提速;真提速杠杆在
重试轮(297s)。方向 2 的 workflow→探针恰好打这个杠杆。

## 信息流三处断点 → 接上

| archSpec 维度 | 改前 | 改后 |
|---|---|---|
| capabilities | 已喂选型 | 不变 |
| **workflow** | 完全没用 | **→ 探针派生**:探针验主流程关键跨轮路径,不再从需求重编偏门场景 |
| **dataModel** | 塞一句话没人用 | **→ stateSchema**:schema 必须实现架构 spec 的实体+字段,不另想 |
| **interfaces** | 塞一句话没人用 | **→ 前端选择**:形状按 interfaces 定,不靠关键词猜 |

## 核心价值:workflow→探针 打重试轮杠杆

改前探针从 requirement 重推一个场景,可能偏门 → 首探 FAIL → 触发整轮 297s 重试
(实测一次复杂装配单笔最大墙钟浪费)。改后探针验**架构主工作流的 happy path**
(turn 1 建中心记录 → 后轮取用),更贴合真实用法、更容易一次过。

## 端到端实证

### HR 全家桶(顺带抓到一个真 bug)
选型出 13 能力 + **7 缺口**(RBAC/审批引擎/薪资引擎/定时结算…)——archSpec 驱动让
选型更严格逐条标缺口,把 HR 系统架构上真缺的东西更完整暴露(vs 之前 arch-first 2-3 缺口)。
但选中的 13 能力里有需要凭证的(未配)→ 验收走"待配置凭证 SKIPPED"分支。

**抓到 bug**:那个 SKIPPED 分支只设 verification、**没 phase()**——直播台一片空白、
账单无探针段,旁观者以为"怎么没验收"。已修:SKIPPED 也上链("验收跳过:待配置凭证 …")。
所以 HR 这次没能验证 workflow→探针(探针根本没跑,凭证挡在前面)。

### 双语读书助手(纯本地、有 workflow、探针会真跑)—— 方向 2 核心验证 ✅
- 选型 7 能力、**0 缺口**;账单:架构 spec 15 + 选型 129 + 探针推导 161 + 验收 25 + 前端 3 = 333s。
- **首探 轮1 ✓(17s)、轮2 ✓(7s)——一次全过,没有 297s 重试轮。** PASS。
- 前端选了 **bilingual-reader 模板**(不是默认 chat-console)——interfaces→前端驱动生效。
- 对比:之前 bilingual 首探 FAIL 过、HR(arch-first 无 workflow 驱动)首探 FAIL 触发 297s 重试。
  workflow 驱动探针验主流程 happy path(建中心记录→取用),首探一次过,避开重试轮。

诚实标注:reader n=1 + 机制论证(探针验主流程而非偏门场景),不是统计强证;但方向明确成立。
遗留可优化:探针推导本身 161s(满档推理绑定),是下一个可打的点。
