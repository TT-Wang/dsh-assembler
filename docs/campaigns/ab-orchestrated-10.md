## 五维判读

1. **质量:B 10/10(严格口径 9+1),A 9/10。** A 唯一的 FAIL 是 h05 医院导诊:被装配
   agent 幻觉"正式挂号数据库技术故障"向用户求助判负,盲重试(294s 重选+重验)仍败。
   B 同场景 346s 一次过——编排者写的 persona 更具体(表已建好直接用/边界明确)是
   可信解释,但 n=1 不定论。B 的 2 次外科重发(s02 换零件、s17)全部二验 PASS;
   冒烟轮还实证了"诊断为 persona 约束不足→收紧重发→过"(不是重掷选型骰子)。
2. **时间:B 中位 341s vs A 516s;Σ3126s vs Σ4573s(−32%)。** 且 B 含架构确认对话轮。
   大胜:s12 看板 143s vs 521s、h01 HR 全家桶 135s vs 446s。B 反输:s03 合同
   (473s vs 248s,match 176s + 考官回退推导)。
3. **成本:辅助思考近平(182.9k vs 175.7k)——"B 省辅助调用"未成立**:match 瘦身省的
   被考官回退推导(满档,单次最高 32.5k 思)花回去了。**主 agent 思考 B −24%**
   (147.7k vs 193.9k)——尽管 B 做了更多决策;A 的膨胀来自受权施工侦察(见 5)。
4. **交互:B 的反问是装配前的架构确认**(可当场改方向,FDE 工作方式);A 的反问是
   装配后的"施工同意"。两臂反问都被驱动器经正规 /api/respond 通道应答
   (顺手根治了历史"澄清解不开"病:ask 走 server-request 通道,queue 文本永远回不了)。
5. **纪律:真义警两臂都是 0**——F6 病类(改/删 preset、自跑探针)在两套契约下都没
   复发。但 A 臂 8/10 场景被(驱动器自动)授权施工后,平均 20+ 次侦察动作、数十 k
   思考 token,推进到写脚手架时撞沙箱升权(danger-full-access)→ 按无头规则撤退,
   脚手架未落盘。这暴露一个产品真问题:**缺件施工需要升权,无头/低权环境必卡**
   ——B 臂"先交付、缺口如实转述"的默认姿态在这个环境下更稳。

## 直构草图(打法 B 的 B 臂表现)

verify 14 次里 **8 次直用编排者草图**(验收 0-53s);6 次回退考官满档推导
(171-306s,贵)。草图被拒的机械闸原因未逐一取证——**提高草图通过率是 B 臂最大的
单点提速杠杆**(把 MARK_RULES 精要更完整地进 verify_preset 描述,或 match 结果里
带一份草图模板)。

## 诚实边界

- 每格 n=1,运行间方差大(昨日同需求 61-385s 实录);可信的是**方向一致性**
  (10 场景 8 场 B 更快、义警/施工足迹全谱为零),不是单点数字。
- A 臂膨胀部分是驱动器自动同意施工所致(真人可能选"暂不处理");但同意后的
  沙箱撞墙与 token 燃烧是真实产品行为。
- B 臂 FDE(多 agent 班子)未跑:emit_preset 已有 sharedDb 参数,但跨 agent
  共享数据探针在 B 模式没有对应物(verify_preset 是单 preset 面),探底待做。

## 结论与下一步

按设计文档判定:**B 臂胜**(质量平/略胜、墙钟 −32%、主 agent 思考 −24%、纪律与
交互占优)。转正(orchestrated 变默认)前建议补:① 草图通过率修复;② FDE 探底;
③ 一轮复跑确认方差。三工具与 flag 已可生产使用:`DSH_ASSEMBLER_MODE=orchestrated`。
